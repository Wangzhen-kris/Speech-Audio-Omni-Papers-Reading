# 一、全双工类
## 1. 《OmniFlatten》
### a. 介绍
文章主要目的是想在全双工对话系统中实现低延迟和自然交互。为了实现这一目的，作者提出了一种多阶段的后训练方案，逐步将LLM微调成可以端到端全双工口语对话的类型。训练过程包括模态对齐、半双工对话学习和全双工对话学习三个阶段。
### b. 核心训练思路：

**1. Pre阶段-对齐：**
使用ASR和TTS数据微调Qwen2-0.5B，让LLM成为语音-文本多模态模型。

**2.   第一阶段-半双工对话训练：**
        
![1.jpg](https://tc-cdn.processon.com/po/63bd4ab6609b3a21680b7be9-689f36676cf9f565dccc9c26)
       通过将用户输入和系统输出的文本和语音流扁平化为单个序列（即扁平化四流数据）来训练半双工对话上的模型，先让模型学会对话模式。
**3. 第二阶段-全双工对话训练第一步：**
        
![2.jpg](https://tc-cdn.processon.com/po/63bd4ab6609b3a21680b7be9-689f3671ac0dbf02ed0c96e4)
       进一步删除用户输入的【文本流】，对剩余的三个steam进行细粒度的分块和对齐，对块进行扁平化，并使用生成的扁平化三流数据继续训练模型。为了处理重叠的语音，引入了基于块的语音-文本标记对齐。即将文本块大小设置为2个标记，将语音块大小设置为10个标记。
**4.     第三阶段-全双工对话训练：**
     
![3.jpg](https://tc-cdn.processon.com/po/63bd4ab6609b3a21680b7be9-689f3688dd82fc52c7665794)
       构建仅包含输入和输出语音的扁平化【双流】数据 ，并继续训练模型以专注于语音到语音生成，从而消除对中间文本的依赖，从而减少延迟，使系统更接近实时交互。
### c. 网络结构和模块拆解
    
![20250815211333.jpg](https://tc-cdn.processon.com/po/63bd4ab6609b3a21680b7be9-689f328c115ae0463c71fe60)
**1. 音频量化和解码是怎么做的？**
- 使用Cosyvoice中的VQ方式：4096码本、50Hz
- Detokenization同样使用CFM+HiFi-GAN

## 2. 《MinMo》
### a. 介绍
文章主要通过大量的训练数据（140万小时）让LLM模型学会更好的对齐，包括：语音转文本对齐、文本转语音对齐、语音转语音对齐和双工交互对齐。为了实现这一目的，作者也是氛围多阶段训练LLM文本模型，最终在语音理解和生成的各种基准测试中实现了最先进的性能，并且还促进了全双工对话。
### b. 核心训练思路：
训练任务由四类组成，包括：Speech-to-Text、Text-to-Speech、Speech-to-Speech 和 Speech-to-ControlToken 任务。
**1. 语音转文本任务：**
此类别由大约 120 万小时的语音-文本配对数据组成，包括自动语音识别 （ASR）、语音转文本翻译 （S2TT）、语言识别 （LID）、上下文偏差语音识别、语音情感识别 （SER）、音频事件检测 （AED）、说话人分析、口语平滑等任务。

**2.   语音转文本任务：**
语音合成数据组成，与训练 CosyVoice 2 所用的数据相同。它包括 170,000 小时的文本-语音配对数据，并支持四种语言：中文、英文、韩语和日语。此外，还有大约 1,000 小时的音频生成数据由指令控制。这些指令被扩展为包括自然语言描述，由 Qwen-Max2 生成，利用人类标记的属性，如情感、语速、方言和角色扮演。
**3. 语音转语音任务：**
语音转语音数据主要来自模拟，包括约 10,000 小时的多轮对话语音和 100 小时风格可控的多轮对话语音。
**4. Speech-to-ControlToken 任务：**
Speech-to-ControlToken 数据主要由两部分组成。第一部分是从现有的真实语音交互数据中提取的，第二部分是使用文本对话数据进行模拟的。**这一部分也是系统中实现自然交互的核心**。
### c. 网络结构和模块拆解
    
![minmo.jpg](https://tc-cdn.processon.com/po/63bd4ab6609b3a21680b7be9-689f3ae166c1742e14d27221)
**1. 如何实现打断？**
- 设计了一个全双工预测器模块，来判断是否开始合成音频：由单层 Transformer 和线性 softmax输出层组成，决定系统是否输出音频，模块的输入是LLM输出的隐状态。

**2. 语音编码器用的是什么？音频量化用的是什么方式？**
- 语音编码器使用预训练的 SenseVoice-Large模块。此外，由于Voice Token LM使用预训练好的CosyVoice2作为初始化，因此音频Token方式也默认同CV2相同，即25Hz的语义token。

**3. Voice Token LM的输入是什么？输入的形式？**
-  在输入到Voice token LM之前，要先过一个Output- Projector得到“语义信息向量”，其输入包含：
    - 1）用户语音编码+LLM最后一层隐状态；
    - 2）5个文本token+LLM最后一层隐状态。
-  语义向量和语音token以5:15的方式交错作为输入。因此延迟：为5a+15b+15c，a是LLM生成一个文本token的时间，b是voice LM生成一个音频token的时间，c是FM+HiFi-GAN生成一个token波形的时间。

## 2. 《VITA-1.5》
### a. 介绍
文章是以GTP-4o的视觉、语音、文本交互为目标，构建的一个功能近似的框架。文章的核心也是：多阶段训练方法，逐步训练LLM理解视觉和语音的能力，让模型最终实现流畅的视觉和语音交互。因此，相较于前面两项工作，该工作又额外新增了视觉理解的能力。
### b. 核心训练思路：
训练任务由3个阶段组成，逐步集成了视觉、文本和语音。正是该训练策略，使得LLM模型逐步引入了视觉和语音理解的能力。值得注意的是：3大训练阶段中，每一个阶段的训练又细分为对齐+理解+SFT三步。
**1. 第一阶段-视觉：**
通过训练视觉适配器（InternViT-300M）并使用描述性标题和视觉QA数据微调模型来专注于视觉语言。此步骤建立了模型的基本视觉功能，从而实现了强大的图像和视频理解。细分步骤如下：
- 对齐：使用20%的Image Caption数据进行训练，其中只有视觉适配器是可训练的，而其他模块是冻结的；
- 理解：使用所有Image Caption数据。在此过程中，视觉模块的编码器和适配器以及LLM是可训练的；
- SFT：使用所有QA数据，同时保留20%的Image Caption数据，以增加数据集的多样性和任务的复杂性。在此过程中，视觉模块的编码器和适配器以及 LLM 是可训练的。

**2. 第二阶段-音频：**
此步骤建立了模型的基本语音功能，从而实现了强大的语音理解。细分步骤如下：
- 对齐-又分为两个阶段：
    - 语音编码器训练：使用11,000小时的语音转录对数据（ASR数据），使用CTC Loss训练编码器模块，让其做ASR任务；
    - 语音适配器训练：使用11,000小时的语音转录对数据（ASR数据），打开LLM参数进行ASR任务训练，在这个过程中还特殊添加了上下文Prompt作为输入。
-  SFT：使用4%的Caption数据和20%的QA数据，其中QA数据约一半的文本问题被替换为使用TTS生成的语音，此阶段的重点是引入带有语音问题和文本答案的QA功能。在这个阶段，视觉编码器和适配器、音频编码器和适配器以及 LLM 都是可训练的。此外，还在LLM的输出中添加了一个分类头。此头用于区分输入是来自语音还是文本。使得模型可以更准确地解释语音输入并高效灵活地处理不同的模态。

**3. 第三阶段-音频输出调谐：**
此步骤在不影响模型基本能力的情况下引入语音输出功能。细分步骤如下：
- 音频编解码器训练：使用3000小时的语音数据，进行音频的Token量化以及Token到音频的训练任务；
- NAR + AR解码器训练：使用3000小时的文本-语音数据，文本和音频首先被Token化。其次，文本嵌入被送到 NAR 语音解码器以获得全局语义特征，然后将这些特征送到 AR 语音解码器，预测相应的语音token。LLM在此阶段被冻结，因此多模态性能不受影响。

### c. 网络结构和模块拆解
![ViTA1.5.jpg](https://tc-cdn.processon.com/po/63bd4ab6609b3a21680b7be9-68a043b59ff7c75d25f3aa59)
**1. 音频编码器用的是什么？**
- 自己训练的一个约350M的参数和12.5Hz的输出帧速率的模块。Mel-filter组特征用作音频编码器的输入，窗口大小为25ms，偏移为10ms。

**2. 音频量化用的是什么方式？**
- TiCodec，大小为 1024 的单个码本，频率为 40Hz 的离散语音令牌。
